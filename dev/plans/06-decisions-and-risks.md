# 06 — Decisions (ADRs) & Risks

## ADRs

| # | Decision | Rationale / Alternatives |
|---|---|---|
| 001 | **Desktop shell: pywebview** (React SPA inside) | Pure-Python launch, system WebView, zero build complexity. Alt: Tauri 2 (later, better packaging), Electron (rejected: heavy), Qt/NiceGUI (rejected: no React). Escape hatch: frontend is shell-agnostic. |
| 002 | **SQLite** as the only database (+FTS5, +sqlite-vec) | Local-first, zero-ops, one file to back up. Alt: Chroma/LanceDB (extra service), Postgres (overkill). Scale is personal — millions of chunks OK. |
| 003 | **Gemini Flash as suggested OCR engine** (user-swappable via Settings) | Best price/quality for math handwriting + diagrams; fast. Any provider works behind `ocr/base.py` + the Settings registry (doc 07); PaddleOCR/local adapter possible later for offline OCR. |
| 004 | **LangChain + LangGraph** for AI orchestration | Provider-agnostic models/tools/structured output; graphs for stateful multi-node pipelines. Alt: hand-rolled (more control, more glue — revisit per-pipeline if LangGraph friction appears). |
| 005 | **Blocks as canonical content format** | One schema across extractions/questions/notes/chat → shared renderers, LLM-serializable, OCR-resolvable images. Alt: raw markdown (loses structure, images not addressable). |
| 006 | **OCR-first multimodal normalization** | Core requirement: text-only models run every pipeline; vision models are an optimization. See 04. |
| 007 | **FSRS** for spaced repetition | Modern, well-validated, simple lib (py-fsrs). Alt: SM-2 (older), Leitner (worse). |
| 008 | **SymPy before LLM** for math grading | Determinism, cost=0, auditability. LLM grading only for free-form/rubric. |
| 009 | **API keys in OS keyring** | Never in DB/files/git. |
| 010 | **In-process job runner + jobs table** | No Redis/Celery for a desktop app; durable via table, resumable, progress on WS. |
| 011 | **Local embeddings by default** (bge-m3 / sentence-transformers) | Free, offline, unlimited re-embedding of OCR fixes; API embeddings opt-in. |
| 012 | **Excalidraw-style canvas on perfect-freehand** (MIT) vs tldraw | tldraw license/watermark constraints; we need stylus strokes + replay + export, which perfect-freehand gives directly. |
| 013 | **English-only UI in v1; i18n wired from day 1** (react-i18next) | User decision. All strings keyed immediately (lint-enforced); adding Greek later = new JSON catalog, zero refactor. |
| 014 | **Profiles without authentication** | Several learners, one machine; `profile_id` scoping in schema from day 1 (cheap now, painful retrofit). It's a switcher, not security — no passwords by design. |
| 015 | **Ollama is a first-class provider** | Preset in the provider wizard (`openai_compatible` @ `localhost:11434/v1`, auto-detect, no key). Enables offline chat/embeddings; OCR stays cloud (Gemini) until a local OCR adapter lands (backlog). |
| 016 | **Linked folders instead of sync** | User decision: no Nextcloud/WebDAV sync service. Materials may reference files in place; hash-based change detection → re-ingest as new extraction version. Originals never moved or modified. |
| 017 | **Periodic source scanning, mtime-first detection** | User decision: background poll per source (default every 5 min, configurable; plus scan on startup and manual "Rescan"). Per file: cheap `stat` (mtime+size) first — unchanged → skip, no hashing; changed → content hash → hash same (e.g. touch) → refresh mtime only; hash differs → offer/auto re-ingest as new version. inotify/watchfiles rejected for now: polling is cross-platform, works on network mounts, and the heuristic makes cost negligible. |
| 018 | **Chat RAG before quiz engine** | Retrieval is the foundation of quizgen + tutor; the chat pipeline is the cheapest place to harden it on real material. Debugging quiz/tutor quality on an unvalidated retriever compounds errors. |
| 019 | **Real eval fixtures from day one** | Golden sets use the author's actual scanned pages/handwriting (collected Phase 0); synthetic samples don't reproduce real failure modes (skew, bleed-through, marginalia, messy math). |
| 020 | **DB-backed skills/prompts, code-seeded** | Users edit AI behavior in the UI (doc 08); code seeds system defaults idempotently and remains the reset point. Alt: prompt files in code only (not user-editable) or DB only (no canonical defaults) — rejected both. |
| 021 | **Behavior contracts with deterministic validators** | "Hint must never reveal the answer" is enforced by code (equivalence-chain leak check), not by prompt phrasing alone. Violations → repair loop → flag; never silent. LLM-judge allowed only where marked, never for answer-leak. |
| 022 | **Equivalence chain over simplify()** | Calculus grading robustness: symbolic simplify + numeric random-point sampling + solveset, any-stage-pass. simplify() alone provably misses equivalent forms; sampling alone misses domain edge cases. |
| 023 | **Unified help taxonomy across quiz & exercise** | One help system (ladder + Socratic + ask-about-this + post-feedback), one audit trail, one independence score. Alt: separate quiz help vs tutor help — rejected: duplicated contracts, incomparable analytics. Exam mode refusal is contract-enforced server-side, not just hidden UI. |
| 024 | **OCR never grades** (handwriting answers) | Stylus answers go through an "interpreted as" confirmation chip — the user confirms/corrects LaTeX *before* submit; only confirmed input is graded. Misreads cost a correction, never a wrong grade. Alt: auto-grade OCR output — rejected: OCR error would punish correct math. |
| 025 | **Follow-through credit in composites** | Real exam practice: later parts graded against the student's earlier (possibly wrong) value via re-parameterized equivalence. Reflects understanding, avoids cascading punishment; per-exam toggle. |
| 026 | **Calm engagement design** | Motivation through visible progress (mastery fills, streaks, goals, next-best-action) rather than pressure mechanics. XP/badges on by default but silent; no leaderboards, no streak-shaming, full off-switch. Spec: doc 09. Alt: aggressive gamification — rejected: effective short-term, corrosive to the "study workbench" trust positioning. |
| 027 | **Two-tier interchange format** (`caq` JSON + `qpkg` zip) | Single-file markdown-shorthand JSON is what external AIs author natively; zip carries assets/checksums for full-fidelity user sharing. Import runs through the *same* contract validators as quizgen — no second quality path, external output is never trusted. Alt: one format — rejected: zips are hostile to LLM authoring, bare JSON can't carry images reliably. |
| 028 | **Import inbox as scanner reuse** | The watched folder is the linked-folder scanner (ADR-017) pointed at an imports directory — one mechanism, two features; disposition by rename (`.imported`/`.rejected`) keeps state visible to external tools. |
| 029 | **Hand-rolled HTTP adapters for model calls; LangChain/LangGraph deferred** | Gateway (`app/ai/gateway.py`) speaks google/openai_compatible/anthropic REST directly via httpx — generate + SSE streaming; retries/cost-table integration still pending. Uses ADR-004's own revisit clause ("revisit per-pipeline if friction appears"): the abstraction we needed (task→model→provider + parts) was much thinner than LangChain's. LangGraph adoption remains planned for true multi-node pipelines (tutor, quizgen graphs); revisit when the first stateful graph lands. |
| 030 | **vec0 tables runtime-created, not Alembic-migrated** | sqlite-vec requires `sqlite_vec.load()` on each connection (wired into the engine connect event); virtual tables can't be created in offline migrations sensibly. `chunk_vecs`/`vec_meta` are created on first store and rebuilt when the embedding model/dim changes (model identity in `vec_meta`). Swap-the-vector-backend escape hatch (risk register) preserved behind `app/storage/vectors.py`. |
| 031 | **Plan-07 provider/task layer pulled forward into Phase 1 (user decision)** | Providers/models/task-assignments + Settings UI landed in Phase 1, not Phase 7, and library folders were added — explicit user scope change (2026-08-18): "api keys in UI; OCR a task, not Gemini-specific". OCR = the `ocr` task routed to any vision-capable assigned model via the gateway; presets (incl. Ollama) are convenience only. |
| 032 | **Local embeddings default (ADR-011) deferred** | sentence-transformers/bge-m3 would pull torch into every install; embeddings currently require a provider model (google / openai-compatible) via the `embeddings` task. Search degrades to FTS-only when unassigned. Revisit at packaging or when offline mode is prioritized. |
| 033 | **Course workspace = soft scope with "All courses" default, not a hard gate** | The rail course selector scopes study pages (quiz/exercises/notes/flashcards/scores) and binds generation, but "All courses" (null) remains the default and a valid mode: all pre-selector content has course_id NULL and a hard gate would render every existing quiz/note/card invisible; cross-course flashcard review is also a real use case. A hard gate appears only when zero courses exist (WorkspaceGate → create/select a course). Revisit if per-course data isolation becomes a requirement (e.g. multi-student use). |
| 034 | **Link-based material model: library owns, courses link** (user decision 2026-08-19) | One material row per document per profile (content-hash dedup goes profile-wide, dropping the per-course scope that created duplicate rows + divergent extractions for the same file in two courses). Allocation becomes `material_links` with scope `course|chapter|section`; `materials.course_id` is demoted to optional "home course" metadata. Cross-course allocation was already possible (section_materials was course-agnostic) — this makes it explicit, validated, surfaced ("also used in …" badges), with unlink ≠ delete and library-delete guards while links exist. Alt: per-course ownership/copies — rejected: duplicate OCR cost, divergent extractions, worse UX for shared textbooks. |
| 035 | **Tree depth fixed at 2 levels: chapter → section** (user decision 2026-08-19) | A1 originally said unlimited nesting; as-built has been 2-level since Phase 2 and it stays. Rationale: outline-AI quality, DnD simplicity, analytics mapping, section-scoped RAG. Desired depth comes from the chapter workspace view (Phase 8B) instead of tree recursion. Supersedes the "unlimited nesting" clause of A1. |
| 036 | **Per-course material ownership; no global library** (user decision 2026-08-19; **supersedes ADR-034 before implementation**) | Every material belongs to exactly one course (`course_id` required); no global library, no cross-course linking. Scoped assignment (course/chapter/section via `material_links`) remains but is strictly intra-course. Consequences accepted: the same document added to two courses = two materials + two extractions (OCR re-runs); blob bytes are still stored once (content-addressed store is invisible plumbing — dedup happens below the material layer). `material_folders` become per-course trees (course → folders → materials), which is the organization win; the Library page scopes by the selected course (rides ADR-033). Legacy course-less materials migrate into an auto-created "Unsorted" course with quick-assign. Alt: link-based global ownership (ADR-034) — rejected by user as conceptually heavier; sharing across courses was hypothetical, separation is daily. |
| 037 | **Linked sources are symlink-style folder nodes; live browse, blob-copy content** (user decision 2026-08-19) | A linked source appears in the course folder tree as a folder node (`material_folders.source_id`), modeled on Linux symlinks: label ≠ target; renaming/moving the node changes only the link; deleting the link never touches files on disk; dangling (target gone) shows a badge with a re-link flow. **Navigation is live**: browsing the node `scandir`s the real target (subdirectories are virtual breadcrumb segments, never stored; follow_symlinks=False + depth cap against cycles; realpath containment against traversal; I/O errors are per-request states, not crashes — network mounts). **One deliberate divergence**: content is still copied into the content-addressed blob store on ingest (codifies the as-built deviation from ADR-016's "reference in place"): originals survive target deletion (OCR QA, backups, re-embed) — symlink for organization, snapshot for content. Un-ingested files seen on browse get a pending badge + explicit ingest (predictable OCR cost). **Unlink keeps materials** (moves to course root; extractions/read-states/section links intact; dialog offers optional deletion). Never write to the target. |
| 038 | **Uniform scoping: placement (scope_type/scope_id) is orthogonal to ownership (course_id)** (user request 2026-08-19, Phase 9 — doc 12) | Every study resource (quiz/exercise/flashcard/note/concept-coverage/chat) is *placed* at course/chapter/section via one polymorphic, strictly intra-course scope pair — the proven `material_links`/`notes.owner_type` pattern generalized — while `course_id` remains the single ownership/purge axis (ADR-036) and concepts stay one course-owned graph with per-node *coverage* links. Roll-up over the fixed 2-level tree (ADR-035) replaces per-level copies; nullable scope keeps unbound "All courses" content valid (ADR-033). Alt: full symmetry (every resource gets course+chapter+section FKs or per-level copies) — rejected: 21 relationships to validate/purge/UX, fragments analytics and dedup without adding meaning. |
| 039 | **Unified node tree: one `tree_nodes` table per course (≤4 node levels), scope = `node_id` FK** (user decision 2026-08-19; **supersedes ADR-035's fixed-2-level clause and simplifies ADR-038 before implementation** — doc 12 rewrite) | Chapters/sections collapse into a self-referential node tree (materialized `path`/`sort_path` for indexed subtree + depth-first queries; every course has an undeletable root node = the course level). All placement (quizzes, exercises, flashcards, notes, material links, concept coverage, chat binding) becomes one `node_id` column with a **composite FK `(node_id, course_id)` → tree_nodes(id, course_id)`** — intra-course placement is *database-enforced*, eliminating ADR-038's polymorphic `scope_type/scope_id` (no-DB-integrity anti-pattern) before it ships. Ownership stays `course_id` (ADR-036); concepts stay one course graph with per-node coverage; note attachment (`owner_type`) stays separate from placement. Outline AI still drafts 2 levels by *policy* (ADR-035's quality rationale survives as policy, not schema); deeper levels are manual. Alt rejected: ADR-038 as drafted (polymorphic scope, three node-ish concepts) — three placement schemes, service-hoped integrity, per-level UI branches. Alt rejected: closure table — 3× write amplification on moves for query patterns already indexable via paths (paths are derived/rebuildable, so the strategy can change later). |
| 040 | **Course-required study content: creation endpoints refuse course-less writes** (user decision 2026-08-20) | Every creation path requires a course: notes, quiz/exercise/flashcard generate + manual create, error-pattern drills, caq/qpkg/inbox imports, Anki import (body `course_id` or required query param; missing → 422). Rationale: after ADR-036/039 everything is course-owned anyway — nullable course on writes produced unplaced orphans and let generation run without retrievable scope. Legacy unbound rows migrated into a per-profile "Unsorted" course server-side. GETs stay optional-scope ("All courses" remains a valid *view*, ADR-033 — it just can't be the target of a write). Frontend: workspace course wins → single existing course fallback → required course select in create/import dialogs → "open a course first" hint on one-click actions (`useRequiredCourse` + `CourseSelectField`). Chat sessions keep nullable course (RAG scope only, no placement). |
| 041 | **Notes live where you explore — no flat global notes page** (user decision 2026-08-20, ADR-040 follow-up) | The notes surface is the workspace Notes tab (course/node roll-up, search, tag chips, pagination); opening a note renders a drawer editor **over the workspace**, driven by a `note` search param on both workspace routes (URL-addressable: back button closes; X/backdrop/Escape strip the param via `closeNote`). A standalone full-page editor exists at `/note/{id}` (palette search + palette-originated creation go there; old `/notes`/`/notes/{id}` URLs redirect). Rail loses the Notes nav item (Workspace = Courses + Library); the rail's course context strip keeps a Notes deep-link into the workspace tab. Rationale: with ADR-039/040 every note is placed in a course tree — a flat global list duplicates the workspace's scoping/search and pulls the user out of context; the drawer keeps the note and its node visible together (breadcrumb course▸node). Alt rejected: keep `/notes` as the primary surface — double navigation paths, two list implementations to keep in sync. |

## Risk register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| WebKitGTK (Linux pywebview) rendering issues with KaTeX/Mermaid/MathLive | Med | High | Phase-0 go/no-go spike; fallback = system Chrome via `pywebview --gui=cef` or browser mode; Tauri migration path |
| OCR/LLM cost & rate-limit surprises | Med | Med | page-level caching, dedup, budgets w/ pause, concurrency caps, backoff |
| LLM generates wrong quiz answers / grading | Med | High | deterministic validators, SymPy checks, `review` flags, golden-set evals in CI, one-click regenerate |
| sqlite-vec quality/limits at scale | Low | Med | hybrid retrieval (BM25+RRF) already; swap vector backend behind `storage/vectors.py` if needed |
| Scope creep (feature catalog is huge) | High | High | **v0.1 walking skeleton defined (end of Phase 4) and may not slip**; P0 beyond it may slip one phase; P1/P2 parked in backlog |
| Handwriting OCR quality for messy math | Med | Med | QA edit UI is first-class; confidence flags; cache keeps re-runs free; model upgrade = config change |
| LangGraph churn / API changes | Med | Low | pipelines isolated in `pipelines/`, thin wrappers, fakes in tests |
| Single-process contention (long OCR job vs UI) | Med | Med | OCR in thread pool, all DB writes short-transactions, WAL busy_timeout |
| Stroke JSON bloat | Med | Low | compressed stroke format, thumbnails, originals on disk not in DB |
| Privacy: material sent to cloud APIs | Certain | Med | documented per-call logging, local/Ollama mode as escape, future local OCR adapter |
| User-edited prompts break generation quality | Med | Med | contracts run on every generation + test-run sandbox shows validator results before save; versioning & rollback; system defaults always restorable |
| LLM-judge validators are themselves wrong | Med | Low | judges marked per-constraint, spot-checked in evals; never used for answer-leak or math equivalence (deterministic only) |
| Malicious/broken imports (zip bombs, path traversal, bad external-AI output) | Med | Med | bomb/depth/size guards, path-traversal checks, mime whitelist, contract validation on every question, provenance recorded, partial-import with flags (doc 11 security) |
| Linked-source files moved/renamed/deleted on disk | High | Low | missing detection on scan, re-link by content hash, status badge in UI; uploaded blobs unaffected |

| 042 | **AI task layer & context engine — one invocation path, inspectable context** (user decision 2026-08-20) | All structured generation tasks (quizgen/exgen/flashcards today; chat later) resolve context through one `ContextResolver` (`scope: node\|subtree\|course` + material include/exclude + notes + concepts + ancestor `ai_hint`s + one-off hint) and run through one `TaskRunner` (skill resolution → JSON repair loop → uniform audit). The UI is one schema-driven GenerateDialog with a live context preview (`POST /ai/context/preview`, no LLM call) — the user sees exactly what will be sent. Chunk retrieval becomes truly hybrid (FTS ⊕ sqlite-vec RRF at chunk level). Rationale: 16 hand-rolled call sites had drifted (JSON extraction ×7, repair loops ×6 with drifting rounds, skill boilerplate ×7, prompts duplicated between pipelines and skill seeds); context was assembled ad-hoc per caller with `retrieve_chunks` silently ignoring embeddings; nothing showed the user what the AI would see. Alternatives rejected: per-pipeline incremental cleanup (keeps N context assembly paths); putting hints on notes-as-tags (mixes student content with instructions; no ancestor inheritance). Chat keeps its own assembly until 10E — its citation/guard contracts are subtle and were not to be risked in the same change. |

| 043 | **AI as a first-class actor: entity mentions, HITL proposals, AI-composed material** (user decision 2026-08-20) | (1) **Mentions** — the ContextBundle's `[M#]/[N#]/[C#]/[T#]` handles are a two-way protocol: prompts carry the registry, models may reference handles in output; backend resolves against the call's registry (out-of-range left literal + repair feedback), frontend renders one `EntityMention` card component everywhere (chat, blocks, explanations). (2) **Proposals** — chat turns may end with a contract-validated, whitelisted action block (`create_note`, `assign_material`, `cover_concept`, `set_node_ai_hint`, generate-*→prefilled dialog, `compose_material`); stored `proposed` in `chat_proposals`, executed only on explicit user approval through existing services, always audited. Generation actions never auto-run — the dialog opens prefilled. (3) **AI-composed material** — new `material.compose` task on the TaskRunner; output is a real material via `create_text` + standard ingest (indexed, citable, assignable), `provenance=ai-composed` badge; explicitly *not* excluded from retrieval by default. Chat goes manifest-first with a deterministic `READ <handle>` tool (rounds 2→3, char budgets). Non-goals: no native function-calling migration, no autonomous actions, MCP stays read-only. Alternatives rejected: LLM function-calling (vendor variance, weaker auditability); free-form JSON actions without whitelist (unsafe); separate "AI documents" table (duplicates material lifecycle — compose writes the same materials pipeline). |

| 044 | **"Study here" becomes a launcher, not a shortcut** (user decision 2026-08-20; post-1.0 backlog, plan 16) | The node-workspace "Study here" CTA stops silently generating an 8-question quiz and instead opens a **study launcher**: a menu of AI actions (Quiz, Exercises, Flashcards, Study guide, Summary sheet, Practice set, Error recap, **Mindmap**, **Write a note**), each routing to the existing `GenerateDialog` (pre-scoped to the node) or a new `NoteComposeDialog`. Two new backend capabilities: a **`mindmap` compose kind** (Mermaid `mindmap` diagram emitted as a composed Material — reuses the existing diagram renderer, no canvas) and **`POST /notes/compose`** (ContextResolver → `note.compose` skill on the `description` task → creates a placed `Note`). Rationale: one CTA was burying a rich, already-built generate surface; the fix is composition of existing pieces, not new infrastructure. Alternatives rejected: a new unified mega-dialog (reimplements `GenerateDialog`'s scope/source/preview logic); a dedicated mindmap canvas (out of scope vs ADR-012); a new `note_compose` task row (a text generation already served by `description`, consistent with `notes.action`). |

| 045 | **Exercise = the generic practice item; flashcards fold in as `card_*` kinds; quizzes stay separate** (user decision 2026-08-20, plan 18 Part B) | One `exercises.kind` taxonomy replaces "exercise = multi-step symbolic problem only": kinds declare an assessment engine (deterministic chain/exact/structural, FSRS-scheduled, or AI-rubric — determinism before LLM always). **One exercise per flashcard** (`card_basic` / `card_reverse` / `card_cloze`): the step prompt is the front, `expected.back` the back; FSRS state stays per card (`fsrs_states.card_id` / `review_log.card_id` re-point to `exercises.id`, column names kept — "card" remains the domain concept); decks are a `deck_ref` string (Anki deck at import). The `flashcards` table is dropped (migration 0026) — no dual source of truth. The card REST surface (`/flashcards/*` routes, `CardOut` shape incl. bare `basic/cloze/reverse` kind strings) is **unchanged**, so the frontend keeps working untouched; exercise list endpoints exclude `card_*` kinds by default so practice views stay clean. Quizzes remain a separate assessment entity (attempts/scoring/exam mode/import-export) — question *types* may mirror exercise kinds but the runner model is different. Alternatives rejected: keep a parallel flashcards table (two practice models to keep in sync forever); one exercise per deck with card steps (couples FSRS to steps, deck-scoped sessions don't match the cross-deck due queue). |
| 046 | **Never-lose-notes: debounced autosave + localStorage draft mirror + beforeunload flush; server-side coalesced pre-write snapshots for history (plan 22 A/B)** (user decision 2026-08-21) | Note bodies autosave 1.5 s after the last keystroke (10 s max latency; 5 s retry on failure) via `useNoteAutosave`; a `ca-note-draft:{id}` localStorage mirror written on the same cadence is the crash-recovery source (banner: Restore/Discard when the mirror is newer than the note's `updated_at`); unmount + `beforeunload` flush best-effort with the mirror as the real net. Concurrent edits: PATCH carries `base_updated_at`, stale → 409 → reload-theirs/keep-mine (compared tz-normalized — SQLite round-trips datetimes naive while in-memory copies are aware). Version history (slice B) snapshots the pre-write row **server-side, coalesced** (≥10 min apart or `force_version`), so autosave spam never floods `note_versions` while discrete events (AI actions, restores, manual "save version") always snapshot. Alternatives rejected: per-save versions (a typing session = 100s of rows); websocket/CRDT sync (single-user local app); optimistic offline queue beyond the mirror (out of proportion). |
| 047 | **Automatic local backups on a scheduler + optional user sync-folder target; boot integrity check with auto-recovery (plan 22 C)** (user decision 2026-08-21) | The app populates its own `backups/` dir: a scheduler runs a validated full backup shortly after startup and every `interval_hours` (default 24), rotates 14 dailies + 8 weekly representatives (only files it named are deleted), and optionally copies each archive atomically into a user-chosen sync folder (e.g. Nextcloud/Dropbox) with the same retention — off-machine redundancy without cloud infrastructure. Every archive is re-opened + integrity-checked after writing (corrupt = discarded). On boot, a corrupt `app.db` is quarantined (never deleted) and the newest *valid* backup restored automatically; the event is recorded and surfaced in Settings → Data. Runtime overrides live in `backup-settings.json` (env `CA_*` values are defaults); the manual download/export path stays for migrations. Alternatives rejected: sqlite `.backup` daemon (no retention/sync/validation story); cloud sync of the live DB (WAL + partial-upload corruption); per-table export (restore completeness risk). |
| 048 | **Trash = snapshot-based `deleted_items`; course deletion guarded by a required fresh backup (plan 22 D)** (user decision 2026-08-21) | Destructive deletes (note/quiz/exercise/chat) snapshot the entity's full subtree as JSON into `deleted_items` (7-day TTL, embedded drawing PNGs so payloads are self-sufficient), then run the existing cascade deletes — no soft-delete columns, so no list query changes anywhere. Restore re-inserts rows with original ids; id collisions (sqlite rowid reuse) are resolved by re-inserting with fresh ids + remapping child FKs. Deletes return `{deleted_item_id}` (200) to power an 8-second Undo strip; a Trash card in Settings → Data manages the window. Course deletion is too big to snapshot: the endpoint refuses without `confirmed_backup`, and the guarded path creates a full backup first. Materials/folders are not trashed (content-addressed blob store + extraction versions + automatic backups cover them). Alternatives rejected: soft-delete flags on every table (touched every query forever, leak-prone); trash only in the UI without snapshots (no crash-safety); snapshotting courses into a row (multi-hundred-MB payloads). |
| 049 | **Notes stay markdown/blocks-canonical; drawings are an inline block type, not a free-position canvas (plan 22 E)** (user decision 2026-08-21) | Handwriting interleaves with text by *reference*: bodies serialize drawings as `![drawing](ca-drawing://N)` markdown images, stored as `{"type":"drawing","drawing_id"}` blocks (server-side parse + validation; unknown ids 422). A tiptap image NodeView renders the blob PNG + collapsible OCR transcript at the block's position; Convert-to-text inserts at the cursor. Strokes remain the editable source of truth (re-OCR, canvas v2 with eraser/colors/widths/pressure/variable height); the ContextResolver feeds drawing OCR to AI tasks *in position* so quizgen/tutor see handwriting where the student wrote it. Full Xournal++ (free-position layered pages, PDF-anchored annotation) is rejected for notes — it would break markdown-canonical bodies, OCR-to-LaTeX, AI note actions and card generation; PDF stroke-layers remain a backlog follow-up. Alternatives rejected: embedded base64 PNGs in markdown (duplicates blobs, uneditable strokes); a separate drawing document type (second editor, no interleave); storing only PNGs (strokes lost). |
| 050 | **Course bundles (`ca-course/v1`): content-only export/import with id remapping; personal data never travels (plan 22 F)** (user decision 2026-08-21) | Sharing a course rides a dedicated zip (manifest + course + tree + concepts + materials-with-extraction + notes-with-drawings + quizzes + exercises + course-scope skill overrides + content-addressed blobs) — **not** the backup format. Import is always import-as-copy under a fresh course with full id remapping (tree paths rebuilt natively via TreeService; extractions written directly with re-chunking + FTS rebuild, no re-OCR/jobs), guarded by a dry-run validation preview.
