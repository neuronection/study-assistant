# Study Assistant 0.13.0

The first stable release of the 0.13 line. Supersedes
`0.13.0-rc.6` and keeps every rc fix. **This is a breaking release: 0.12.x data is
not migrated.**

## What changed since rc.6

- **Onboarding** — the first-run wizard is deployment-aware (no working-directory
  step on server identity), the data location is read-only until you explicitly
  choose **Change folder…**, and provider setup now reuses the same grid/form as
  Settings. Wizard provider setup binds curated defaults and the defaults step
  uses the same task-assignment picker as Settings, filling any still-empty
  capability from the enabled models.
- **Capture and reading** — capture inbox, offline capture journal, multi-page
  scan assembly, document highlights, the installable PWA/mobile shell and the
  secure-connection report.
- **Study loop** — FSRS pace settings, review filters/preview/daily cap,
  retention and workload reports, and the adaptive **Plan my week**.
- **Lectures and audio** — resumable lecture recording, timestamped transcripts,
  transcript split/merge and deep links, lecture moments and cards, a global
  audio player, offline audio downloads, voice settings and spoken tutor replies.
- **Practice and artifacts** — exam papers, diagram-label questions, the verified
  Problem Desk, Studio slide decks/handouts, the media player/transcript timeline
  and the typed artifact registry with narrated topics.
- **AI and settings** — exact micro-USD cost and provenance in Data & Cost, the
  shared account-session list, family auth-kit 0.6 secrets/opaque credentials,
  the source-grammar contract, and the shared command surfaces/dictation gate.
- **Performance and activation** — route splitting with the bundle budget,
  first-run funnel events, one-time contextual tips, the study coach strip and
  the searchable feature map.

The rc.6 changes remain: one startup flow, automatic quarantine of old data and
PostgreSQL volume preflight.

## Upgrade (required)

0.13 rebuilds the datastore schema (UUID identities, the squashed baseline). On
first launch the old datastore is moved into a `previous-datastore-<timestamp>`
folder and the app starts fresh; if the move cannot happen (another instance
running, permissions) it refuses with `STARTUP-ERROR.txt`. 0.12.x backups are
not restorable by 0.13 — they stay in the kept folder.

1. Install 0.13 and launch it. The old datastore is moved aside automatically
   (nothing deleted).
2. Read the one-time notice: it names the `previous-datastore-<timestamp>`
   folder. Copy the path if you want to keep it.
3. Complete onboarding. Backups made by 0.13 restore normally; 0.12.x backups
   stay in the kept folder (0.13 cannot read them).

## Highlights

- **Token-aware retrieval** — offline tokenizer with real token accounting; a v2
  token-window chunker that builds beside the v1 space, backfills, passes
  coverage/quality and cuts over; bounded live indexing progress in
  Settings → Indexing.
- **Retrieval operations** — spaces, provisioning, coverage, quality
  compare/gate, alerts and a read-only observation surface (runs, spaces,
  quality, query health, usage).
- **Cloud calendars** — bind Google, Microsoft 365, Nextcloud, iCloud, Fastmail,
  CalDAV or an ICS feed; exam, deadline and milestone dates project as all-day
  events; two-way sync is opt-in; credentials stay in the OS keyring.
- **Connected sources and academic ingest** — arXiv/OpenAlex/Crossref discovery,
  `.bib`/`.ris`, `.ics`, markdown vaults, WebDAV/Drive/Dropbox/OneDrive/Zotero/
  Anki; every import lands as a suggestion you review.
- **Extension host** — validated manifests, bundled connectors and MCP
  instances; the frozen bundle and the Docker image ship the family contracts
  and extension data.
- **PostgreSQL 16 web mode**, profiles/identity, and the 0.13 hardening round
  (restore safety, typed schema-break refusal, packaging completeness,
  CSP/OAuth callback, calendar sync safety).

## Known limitations

- **CalDAV recurring events** (Nextcloud/iCloud/Fastmail) can appear as a single
  item at the series start; in-window occurrence expansion is a follow-up in the
  0.13 line.
- **Google/Microsoft calendar OAuth** needs deployment client IDs
  (`SA_GOOGLE_CLIENT_ID` / `SA_MICROSOFT_CLIENT_ID`); CalDAV/ICS work out of the
  box.
- **Windows** is built and smoke-tested by this tag's CI.
- **No data migration from 0.12.x** (by design; see Upgrade).
